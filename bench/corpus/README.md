# Benchmark corpus

Generated by `bench/gen_corpus.py` (seed `0x1CB0`). Deterministic:
regenerating gives byte-identical files. Do not hand-edit.

## `small_ints.cbor` -- 58 bytes

Every integer head width in one tiny document: 0..23 inline, then the 1/2/4/8-byte forms, positive and negative, plus the simple values.

## `flat_array.cbor` -- 163,797 bytes

One flat array of 60k integers spread across every head width. No nesting at all: this is the pure item-decode loop.

## `deep_nest.cbor` -- 191,490 bytes

4000 independently nested chains, each 40 arrays deep with a small map at the bottom. Depth stresses the parser's container enter/leave path; the repeat count is what pushes it to a realistic size.

## `map_heavy.cbor` -- 338,938 bytes

3000 records, each an 8-key map of short text keys, one of which nests a further 3-key map. String-keyed map lookup shape, the common config / telemetry document.

## `text_utf8.cbor` -- 563,721 bytes

400 text strings of mixed scripts: 1-byte ASCII, 2-byte Cyrillic/Greek, 3-byte CJK and 4-byte astral (emoji, so surrogate-pair territory for any UTF-16 consumer). This is the UTF-8 validation and escaping path.

## `bytes_heavy.cbor` -- 628,060 bytes

1200 opaque byte strings, 16 B to 2 KiB, plus a few empties. Pretty printing renders these as hex, so this is the slowest per-input-byte workload in the corpus by a wide margin.

## `indefinite.cbor` -- 182,665 bytes

Indefinite-length everything: outer array, per-record maps, and chunked byte and text strings. Exercises the break-handling and chunk-iteration code that the definite-length files never touch.

## `tagged.cbor` -- 97,891 bytes

Tagged values -- epoch times, bignums, decimal fractions, base64 hints -- wrapped around the types above. Tags are a separate decode path and none of the other files carry one.
